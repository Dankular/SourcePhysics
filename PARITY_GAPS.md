# Remaining parity gates

This is the completion ledger. An adapter is not complete until Source/reference evidence and a differential test exercise the same behavior.

## Implemented and locally verified

- Source movement dispatch, full-pitch input, acceleration, friction, gravity ordering, stepping, Source TryPlayerMove plane clipping/crease/reversal rules, post-clear-sweep stationary-hull validation, separate single-push FullTossMove collision resolution, crouch timing with Source active-hull lifetime and airborne exception, ladder-plane movement/jump-off, ladder/base velocity, water drift/jump/friction/acceleration, water-jump gravity exclusion, authored water-current base velocity and base-velocity ordering, ground categorization, Source surface-friction scaling/cap and upward-motion fallback, and explicit observer fixed/death/freeze, in-eye/chase target-follow, roaming noclip, and clipped-roaming dispatch.
- Jolt fixed-step host and independently tested accumulator clock (authoritative tick order, long-frame consumption, remainder preservation, and input validation), deterministic native-world teardown (body/listener/system/foundation ordering), collision policy, static meshes, character queries, Source CheckWater feet/midpoint/eye sampling for authored volumes through the live Jolt query bridge, body runtime controls, sensor-aware trigger enter/stay/exit events, explicit unit conversion, and the referenced VPhysics fluid-touch linear/angular damping law.
- Rigid-body capture/restore (including Source body user-data identity), prediction replay, projectile CCD/penetration contract and hitscan query.
- Stride components for the physics host, character movement, rigid bodies, static meshes, projectile movement and hitscan tracing; host initialization is idempotent and dependency components can ensure it exists regardless of Stride script start order; character command sampling plus movement/projectile recordings consume the host's authoritative fixed-tick event, and opt-in rigid-body recording captures immediately after Jolt contact flushing on that same tick. The Source vehicle data contract (controls, operating state, body, wheel, suspension, axle, steering, engine/transmission and wheel contacts) is also represented and validated, but its fixed-tick dynamics remain gated on the safe Jolt vehicle/constraint lifecycle and title-authored assets.
- The evidence-profile loader consumes both wrapped evidence values and authored numeric character values, including standing/crouched eye heights used by view transitions.
- Authored movement profiles are validated at load and Jolt-host construction: numeric values must be finite, required non-negative quantities cannot be negative, bump/clip limits cannot be zero, and character extents must be positive; regression coverage rejects invalid profiles.
- Differential recording/command serialization and comparison for movement (including move axes, up-move, buttons, full view yaw/pitch and jump-edge/duck-transition history), rigid-body ticks (body snapshots, contact additions/persistence/removals, and explicit gameplay impulses), seeded hitscan shots (including resolved ammo/damage/flags/force/water decisions), and projectile ticks, including timing, pose, movement state, contacts, impulses, water-jump, fall velocity, surface state, penetration power and impact metadata; rigid-body comparison reports numeric maxima plus body/contact/impulse divergence; authoritative correction payloads carry simulation tick, acknowledged command sequence, movement state and optional Jolt world state, and bounded historical world rewinds restore live state through a scoped lag-compensation handle.
- Authored surface manifest serialization/validation, injectable contact-material combine policy, and profile-driven standing/crouched character hull extents.
- Source contents masks (`MASK_SHOT`, `MASK_PLAYERSOLID` and authored body contents) are applied by hitscan/projectile body filters, with explicit water/shot regression coverage.
- Source `FireBulletsInfo_t` field mapping, per-shot Source reseeding, first-shot accuracy, player-damage selection, underwater/surface-impact flag handling, AmmoDef-resolved bullet force and force scaling, persistent tracer cadence, authored studio-style hitbox refinement (Source-unit bounds, fixed-tick body/bone pose updates and hit metadata), ordered impact events, optional target-resolver `TraceAttack`/`CMultiDamage` dispatch with explicit Source entity-identity grouping, precision multi-hit Jolt ray collection, entry/exit penetration integration, and the referenced aggregation contract are implemented and recorded.
